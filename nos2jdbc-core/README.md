# nos2jdbc-core

`nos2jdbc-core` is the core module of [nos2jdbc](https://github.com/ns2j/nos2jdbc), a library based on S2JDBC that removes the dependency on the Seasar2 Container.

It provides database access through Java objects, SQL statements, and SQL files. It also includes extensions for entity mapping, embedded objects, and JavaBean/Record conversion.

## Features

- S2JDBC-style database access APIs
- CRUD operations and entity-based queries
- Conditional queries, joins, and related entity loading
- SQL-based queries using `selectBySql` and `selectBySqlFile`
- Mapping SQL results to entities, including queries with custom result columns
- Support for `@Embedded`, `@Embeddable`, and `@EmbeddedId`
- Queries that do not require inverse relationship fields
- Utilities for converting between JavaBeans and Java Records

## Requirements

- Java 17 or later
- Maven
- A JDBC driver for your database
- A configured `DataSource`

## Installation

Add the following dependency to your Maven project:

```xml
<dependency>
    <groupId>com.github.ns2j</groupId>
    <artifactId>nos2jdbc-core</artifactId>
    <version>2.0.0</version>
</dependency>
```

The core module depends on `nos2jdbc-util`. Maven resolves this dependency automatically.

You must also provide the JDBC driver and configure the `DataSource` and transaction management appropriate for your application.

## Basic usage

`nos2jdbc-core` provides the `JdbcManager` API for database operations.

For example, an entity can be retrieved using an entity-based query:

```java
List<Employee> employees =
    jdbcManager.from(Employee.class).getResultList();
```

The `JdbcManager` API supports entity retrieval, insertion, updates, deletion, conditional queries, joins, and SQL-based queries.

The following APIs are available for SQL-based access:

- `selectBySql`
- `selectBySqlFile`

These allow applications to use SQL directly when entity-based queries are insufficient.

The `JdbcManager` instance must be configured with the application's database connection and transaction management before use.

## Mapping SQL results to entities

SQL queries can be mapped to entity classes using the SQL selection APIs.

The `@NonAuto` and `@NoFk` annotations provide additional control over automatic mapping and foreign-key handling.

This is useful when writing custom SQL, including aggregate queries and queries that return columns different from those generated by ordinary entity-based queries.

The mapping functionality also supports queries in which an entity's ID is `null`, which can be useful for results such as `ROLLUP` and other aggregate queries.

## Embedded objects

The core module supports the following annotations:

- `@Embedded`
- `@Embeddable`
- `@EmbeddedId`

These annotations allow an entity to contain an embedded value object or use an embedded composite primary key.

For example:

```java
@Embeddable
public class Address {
    private String city;

    // getters and setters
}
```

```java
@Entity
public class Customer {
    @Id
    private Integer id;

    @Embedded
    private Address address;

    // getters and setters
}
```

Embedded properties are flattened for database column mapping. For example, the property path `address.city` is represented by the column name `address__city`.

The dotted property path is also supported when resolving property metadata.

Embedded-object support is integrated with entity metadata, result mapping, SQL-file parameter handling, and embedded IDs.

## Queries without inverse relationship fields

The following methods are available:

- `getSingleResultWithoutInverseField()`
- `getResultListWithoutInverseField()`

These methods are useful when retrieving related entities without defining inverse relationship fields solely for JSON serialization or object navigation.

They can help avoid cyclic object references when the resulting entity graph is serialized.

## JavaBean and Record utilities

The `org.seasar.framework.beans.util.Records` utility provides methods for working with JavaBeans and Java Records.

The available functionality includes:

- `createRecord`
- `createRecordList`
- `copyToBean`

These utilities support conversion between JavaBeans and Records, including nested data and lists.

They are useful when applications need to separate persistence entities from data-transfer objects.
